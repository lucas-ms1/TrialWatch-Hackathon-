# Connected intervention API v1

Local deterministic worksheet. No extraction model, weighted opportunity score, probability or advocacy execution. All decisions are proposals; pending rights analysis remains pending.

Initialize `InterventionService(store)` as `store.interventions` after rights initialization. Routes:

- GET `/api/interventions/state/<candidate_id>` → `state(cid)`.
- GET `/api/interventions/export/<recommendation_id>?format=md|json` → `export(rid)` and `render_intervention_markdown`.
- POST `/api/interventions/contexts/<candidate_id>` → `context(cid,payload)`.
- POST `/api/interventions/proposals/<candidate_id>` → `propose(cid,payload)`.
- POST `/api/interventions/reviews/<recommendation_id>` → `review(rid,payload)`.
- POST `/api/interventions/followups/<recommendation_id>` → `followup(rid,payload)`.

`state(cid)` returns `candidate_id`, `context`, `context_history`, `recommendations` (each includes `stale`, `stale_reasons`, `review_status`, `reviews`, `followups`), `latest`, `example` (complete synthetic context/proposal/followup inputs), `dispositions`, `routes`, `disclaimer`. `context` and `latest` may be null. Synthetic example is a software fixture; human names are demonstration labels.

Context input has exactly `schema_version: "intervention-context/1"`, `expected_revision`, `author`, `origin` (`manual|ai_prepared|synthetic_prepared`), `evidence_cutoff` (YYYY-MM-DD), `sources`, `source_texts`, `claims`, `unknowns`, `cluster`, `comparables`. Sources use the existing dossier source fields. Each claim has `id`, `topic`, `text`, `source_id`, `excerpt`, `locator`, `relevant_date` (YYYY-MM-DD or null), `date_note`, `attribution`, `uncertainty`, `freshness_note`. Its exact excerpt must occur in its own supplied source text. Topics: `procedure|deadline|issue|affected_groups|organization|attention|institution|issue_position|legal_opportunity|capacity|harm|preferences|party_label|country_indicator|historical_action|historical_outcome`.

`cluster` is null or `{candidate_ids, memberships, reviewer, reason, reviewed_context_ids}`. Memberships contain `{candidate_id, basis, material_differences, identity_uncertainty}` for exactly the listed candidates (at least two, including the primary case). This is an explicit named-human candidate-link decision, not a movement finding, identity merge or authentication. `reviewed_context_ids` must resolve to context passages. `comparables` is an array of `{label, basis, material_differences, action_context_ids, outcome_context_ids, period, contribution, limitations}`; contribution is an explanation distinguishing documented contribution from sequence/unknown, never an automatic effectiveness claim.

Proposal input has exactly `expected_revision`, `expected_context_revision`, `expected_assessment_revision`, `author`, `origin`, `dimension_ids`, `selected_option_id`, `requested_disposition`, `options`, `rationale`. At least two options, including a deferral alternative, are required. Each option has exactly `id`, `label`, `route`, `actor`, `authority`, `objective`, `beneficiary`, `support_context_ids`, `contrary_context_ids`, `authority_context_ids`, `timing_context_ids`, `feasibility_context_ids`, `harm_context_ids`, `preferences_context_ids`, `timing_window`, `preconditions`, `blocking_unknowns`, `benefits`, `harms`, `alternative_explanations`, `next_step`, `reconsideration_trigger`, `factors`. Factors contain `urgency` (`unknown|routine|time_sensitive`), `opportunity` (`unknown|not_established|supported`), `feasibility` (`unknown|needs_verification|feasible`), `harm` (`unknown|material_risk|mitigated`), `preferences` (`unknown|requested|opposed`) and `reason`. Legal concern is separately snapshotted from exact selected rights dimensions.

Routes: `legal_support|partner_coordination|quiet_engagement|public_advocacy|policy_advocacy|mechanism_referral|verification|deferral`. Dispositions: `intervene_now|prepare_verify|refer_coordinate|defer|against|insufficient_basis`. Explicit gates evaluate the requested disposition: deadline/party identity alone cannot establish opportunity. Immediate action requires sourced issue-specific opportunity/authority, dated timing if urgent, feasible capacity, examined/mitigated harms, expressed preferences and no blocking unknowns. Unsupported immediate action becomes preparation or insufficient basis with visible rule reasons. Other dispositions retain their own route, prerequisites and uncertainties.

Review input has exactly `expected_review_revision`, `reviewer`, `decision` (`accept|revise|reject|defer`), `reason`, `dimension_ids`, `context_claim_ids`, `revised_disposition` (one disposition or null), `revision_note` (string; required for revise). Exact dimension scope matches the proposal; context scope includes every passage referenced by all compared options/comparables/cluster. Revised human disposition is separately attributed and preserves the original proposal. Stale proposals cannot be accepted/revised; defer/reject can record a stale historical judgment.

Followup input has exactly `expected_sequence`, `author`, `kind` (`observed_action|observed_outcome|conditional_scenario|unknown_outcome`), `text`, `event_date` (YYYY-MM-DD or null), `period`, `contribution`, `source` (existing source record or null), `source_text` (string or null), `excerpt` (string or null), `locator` (string or null), `uncertainty`. Actual actions/outcomes need a resolving source and exact supplied excerpt. Conditional scenarios are explicitly forecasts without probability; they cannot be relabelled observed outcomes. No action is executed by saving a followup.

Context/proposals/reviews/followups are append-only. Recommendations snapshot full linked rights exports, current context, all options and exact dependencies. Context changes, evidence corrections, reassessments and rights-review changes flag earlier recommendations stale. New proposals need fresh scoped review. Exports retain original snapshots, current dependency warnings, every option/alternative, contrary passages, review/followup history and conditional-versus-observed status.

Sources published after the stated evidence cutoff are rejected; linked rights sources newer than the context cutoff require a refreshed context. Unknown publication/retrieval dates remain unknown. Source text is kept separately for context validation, excluded from decision exports. Markdown context references use explicit validated-ID anchors and retain canonical source links plus exact passage locators.

Run `python -m unittest discover -s tests -p test_intervention.py -v` for nine focused software checks, or `python scripts/rehearse_intervention.py` for a complete fictional rehearsal with retained local state, current/stale cited exports and receipt under ignored `outputs/intervention_rehearsal/`. The rehearsal simulates reviewer names explicitly; it is not actual human legal review, an advocacy execution or evidence of effectiveness.
